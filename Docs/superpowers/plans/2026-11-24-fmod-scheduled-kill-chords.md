# FMOD 예약 원샷 1차 (측정 · 스파이크 · 처치 화음) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 처치 화음을 음악 타임라인 노트에서 "Unity가 박에 맞춰 예약 재생하는 악기 원샷"으로 옮기고, 스타일별 음색과 콤보·긴장도 확장음을 되살린다.

**Architecture:** 음악 이벤트(`event:/Music/ChordPulseGame`)는 박 시계로 남는다. `MusicConductor`가 박 → DSP 시각을 `BeatClock`에 기록하고, `OneShotScheduler`가 `event:/Inst/<악기>`(파라미터 `Note`)를 그 시각에 예약 시작한다. 무엇을 울릴지는 Python 생성기가 만든 C# 표(`*.g.cs`)를 `KillChordVoicer`가 읽어 정한다.

**Tech Stack:** Unity 6 + FMOD for Unity 2.02 (Studio API), FMOD Studio 2.02.35 (`fmodstudiocl.exe` 스크립트), Python 3 + numpy/scipy (생성기·분석), Unity Test Framework 1.6 (EditMode).

**Spec:** `Docs/superpowers/specs/2026-11-24-fmod-scheduled-layers-design.md` — 이 계획은 스펙 6장의 0~2단계만 다룬다. 3단계(믹서·전역 파라미터) 이후는 Task 3의 스파이크 결과를 보고 별도 계획으로 쓴다.

## Global Constraints

- 박 대비 어택 오차: 평균 ≤ 2 ms, 최대 ≤ 5 ms (구간 점프 직후, 0.4박 미만 선행 포함).
- Studio CPU(`StudioSystem.getCPUUsage`의 update): 기준 녹음 시나리오에서 지금 값(약 11%) 이하.
- 처치 화음 레벨: 신스팝 기준 3색 × 3음 매 박 RMS 약 -21.7 dBFS에 스타일별 ±1 dB.
- 처치 화음 박 선택 규칙은 지금 그대로: 다음 박이 0.4박 이상 남았으면 다음 박, 아니면 그 다음 박 (`ChordLeadBeats = 0.4`), 같은 펄스의 처치는 같은 박에 합류.
- 스타일별 악기 표·보이싱·확장음 규칙은 `FMOD/Tools/kill_voices.py`의 값 그대로 (9-7 표).
- 피버 중 처치 화음은 스타일 0 · 콤보 0 · 긴장도 0으로 연주.
- 생성기는 멱등(다시 돌려도 같은 결과). 큰 스크립트 뒤 `-build`는 별도 명령으로 실행하고 뱅크 시각 확인, 빌드 후 `Build/Desktop/*.bank`를 `Assets/StreamingAssets`로 복사.
- FMOD CLI: `"C:\Program Files\FMOD SoundSystem\FMOD Studio 2.02.35\fmodstudiocl.exe"`, FMOD Studio는 닫은 상태에서 실행.
- 생성된 C#은 `Assets/Scripts/Audio/Generated/`에 두고 첫 줄에 "Generated by … - edit the Python file" 주석.
- 웹 데모는 Task 1에서 태그 `web-demo`로 고정한다. 이후 HTML5 뱅크는 신경 쓰지 않는다.

## Review Focus

1. **구간 점프가 걸친 예약** — 프레이즈 경계 너머 박을 이미 예약했는데 `NextSection`이 바뀌면(피버 보류 등) 그 노트는 새 템포 기준 시각으로 다시 예약돼야 한다. → Task 5 `Reschedules_WhenTempoChangesAfterBoundary` 테스트.
2. **정지·재시작 중 남은 예약** — `StopMusic()` 뒤 예약 인스턴스가 울리면 안 된다. → Task 5 `StopAll_ReleasesPending` 테스트 + Task 6 수동 확인.
3. **동시 처치 폭주** — 한 박에 3색 × 보이싱 3 + 확장음이면 박당 최대 21음. 인스턴스 상한을 넘으면 오래된 것부터 빼고 끊김 없이 이어져야 한다. → Task 6 캡처 시나리오 `heavy` + CPU 기준.
4. **프레이즈 첫 박도 어택 보정** (최종 수정 R19로 변경) — 옛 생성기가 구간 점프 착지 박(프레이즈 첫 박)에서 앞당기지 않은 것은 타임라인 노트가 점프 앞에 놓일 수 없어서였다. DSP 예약 원샷은 그 제약이 없으므로 모든 박에 `InstrumentTable.OnsetSeconds`를 적용한다 (안 하면 Guitar·Harp 어택이 약 45 ms 늦음). 착지 박 시작 시각은 `BeatClock`의 예측 앵커에서 온다. → Task 4 `PhraseDownbeat_AppliesOnsetShift`, `OneShotSchedulerTests.PhraseLanding_OnsetShiftUsesPredictedAnchor` 테스트.
5. **음악 시작 전·첫 박 전 처치** — `BeatClock`에 앵커가 없을 때 `QueueKillChord`가 예외 없이 -1을 돌려준다(지금과 같음). → Task 5 `DspAt_ReturnsFalse_BeforeFirstAnchor`.
