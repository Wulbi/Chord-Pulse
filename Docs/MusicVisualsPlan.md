# Chord Pulse — 음악 연출 계획 (손님 루프 + 적응형 배경 루프)

> 오디오 쪽 현황: [AdaptiveAudioPlan.md](AdaptiveAudioPlan.md) 7장(특색 루프, 12종), 8장(적응형 배경 4축).
> 손님 루프 연출의 코드 구조(데이터·연출기·스타일): [FeatureLoopVisuals.md](FeatureLoopVisuals.md).
> 이 문서는 **무엇을 어디에 어떻게 보여줄지**를 정한다. 구현 구조는 위 문서를 따른다.

## 0. 원칙

1. **화면 믹싱 = 소리 믹싱.** 소리에서 어떤 레이어가 다른 레이어 밑에 깔리거나 덕킹되면 화면도 똑같이 한다.
   - 예: `Danger`(체력 1)일 때 반주는 로우패스로 먹먹해지지만 손님 루프와 처치 화음은 또렷하다. 화면도 배경 연출만 어두워지고 손님 연출은 밝게 남는다.
2. **시간 단위가 다르면 자리도 다르게.** 오디오의 네 축은 움직이는 속도가 다르다(즉시 / 마디 / 프레이즈 / 2~4프레이즈). 화면에서도 축마다 다른 영역을 맡겨서, 겹쳐도 어지럽지 않게 한다.
3. **아레나 안쪽은 게임플레이 전용.** 적, 플레이어 펄스, 코어만 있다. 음악 연출은 아레나 경계선부터 바깥에서만 한다.
   - 중앙에서 퍼지는 원은 플레이어 펄스와 헷갈리므로 금지. 예외는 피버 시작·끝 리플뿐이다.
4. **적 색과 겹치지 않는 팔레트.** 적·처치 색은 빨강·파랑·노랑이다. 연출은 채도를 낮추거나, 금색·민트·보라·분홍처럼 비켜 가는 색을 쓴다.
5. **미리 아는 것은 미리 보여준다.** 프레이즈 단위 결정(구간, 스타일, 변형, 손님 루프)은 한 프레이즈 앞서 정해진다(`Upcoming*`). 바뀌기 1박 전에 예고한다.

## 1. 화면 영역 배치

```
┌──────────────────────────────────────────────┐
│ Z0 배경색  ── 코드 틴트 · 스타일 팔레트 · 에너지 밝기          │
│   Z1 배경 원경 ── 스타일 모티프 (느리게, 아주 흐리게)          │
│   Z2 바깥 띠 ── 손님 루프 연출 (혜성·새·종·링 궤도·충격파)     │
│      ╭──────────────╮                            │
│      │ Z3 경계 링 ── 킥/스네어, 콤보, 변형 필, 위기감 떨림 │
│      │   Z4 아레나 안 ── 게임플레이만             │
│      ╰──────────────╯                            │
│ Z5 화면 가장자리(비네트) ── 위기감·Danger·Hurt              │
└──────────────────────────────────────────────┘
```

| 영역 | 담당 축 | 변하는 속도 | 그리는 순서 |
|---|---|---|---|
| Z0 배경색 | 코드(C·Am·F·G), `ArrangementIntensity`, `BedStyle`, 숨 돌리기 | 마디 ~ 프레이즈 | 카메라 배경색 |
| Z1 배경 원경 | `BedStyle` 모티프 | 2~4프레이즈 | -5 |
| Z2 바깥 띠 | 손님 루프 12종, 피버 연출 | 음표 단위 | -3 |
| Z3 경계 링 | `BedStyle`(모양), `Intensity`(두께), `Variation`(질감), `Combo`(바깥 겹), `Tension`(일그러짐), 킥·스네어 | 박 ~ 프레이즈 | -1 (기존 경계선) |
| Z5 비네트 | `Tension`, `Danger`, `Hurt` | 즉시 (수백 ms) | 최상단, 반투명 |

## 2. 적응형 배경 루프 연출

### 2-0. 경계 링과 배경 = 배경 루프의 얼굴

경계 링(Z3)과 배경(Z0·Z1)은 **지금 깔려 있는 배경 루프가 어떤 상태인지**를 보여준다. 배경 루프의 각 축이 링과 배경의 서로 다른 속성 하나씩을 맡는다. 그래서 여러 축이 동시에 바뀌어도 서로 덮어쓰지 않고 한 화면에 함께 읽힌다.

| 배경 루프 축 | 바뀌는 시점 | 경계 링에서 맡는 속성 | 배경에서 맡는 속성 |
|---|---|---|---|
| 스타일 `BedStyle` | 2~4프레이즈 | **모양** (선 / 구슬 / 마디 / 이중 링) + 기본 색 | **팔레트** + 원경 모티프 (Z1) |
| 코드 (C·Am·F·G) | 마디 | 색조 살짝 | 색조 (기존) |
| 에너지 `Intensity` | 프레이즈 | **두께·밝기**, 엇박 눈금 | **밝기** (기존) |
| 패턴 변형 `Variation` | 프레이즈 | **움직임 질감** (숨쉼, 걷는 점, 필) | — |
| 콤보 `Combo` | 마디 | **바깥 겹 링** (점선 → 후광 → 반짝임) | — |
| 위기감 `Tension`·`Danger`·`Hurt` | 즉시 | **일그러짐**, 순간 수축 | **채도** (Danger), 가장자리 비네트 (Z5) |
| 숨 돌리기 | 프레이즈 | 드리미 모양 + 킥 펄스 절반 | 드리미 팔레트 + 탈채도 (기존) |
| 피버 | 프레이즈 | 흰 킥 펄스 (기존) | 채도 최대 + 흰 플래시 (기존) |

**전환 타이밍** — "타이밍이 안 맞는" 느낌을 막기 위한 규칙
- 프레이즈 단위 축(스타일, 변형, 에너지, 숨 돌리기, 피버)은 **화면 박 기준 프레이즈 첫 박**에 바뀐다. 1박 전부터 크로스페이드를 시작해서 첫 박에 완료한다 (`Upcoming*`로 미리 안다).
- `SoundManager.CurrentStyle`·`CurrentVariation`은 FMOD에 보낸 값이라 앞보기(0.15초)만큼 **일찍** 바뀐다. 화면은 이 값을 바로 쓰지 말고, 위처럼 화면 박의 프레이즈 경계에서 `Upcoming*` → 현재로 넘긴다 (4-2).
- 콤보는 마디 첫 박, 위기감은 FMOD가 실제로 따라가는 값(부드럽게 변함)을 그대로 쓴다.

#### 스타일별 링 모양

| 스타일 | 링 모양 | 링이 반응하는 소리 |
|---|---|---|
| 0 신스팝 | 매끈한 네온 선 (기존 경계선) | 킥 펄스, 스네어 플래시 (기존) |
| 1 라틴 | **구슬 링**: 작은 점 32개가 원을 이룸 | 라틴 클라베 박에 해당 위치 구슬이 커짐, 콩가에 구슬이 살짝 흔들림 |
| 2 펑크 | **마디 링**: 16조각으로 나뉜 원, 조각 사이 틈 | 16분 햇마다 조각 하나씩 순서대로 밝아짐 (한 박에 4조각), 기타 "찡"(2·4박)에 전체 번쩍 |
| 3 드리미 | **이중 링**: 흐린 두꺼운 링 + 안쪽 얇은 링 | 코러스 화음마다 바깥 링이 천천히 호흡 (마디당 1회) |

- 모양이 바뀌어도 링의 **반지름과 위치는 그대로**다. 경계선이 어디인지 항상 읽혀야 한다.
- 구슬·조각 사이 틈은 링 둘레의 30% 이하로 한다. 적이 경계를 넘는 순간이 끊겨 보이지 않게.
- 전환할 때는 모양을 1박에 걸쳐 모프한다 (선 → 구슬: 선이 점점 끊어지며 점으로 뭉침).
- 손님 루프 중 Latin Groove는 라틴 스타일에서 선택되지 않으므로 구슬 링과 링 궤도 점이 함께 나오지 않는다. Mallet Hook의 카우벨 점은 0.5배라서 구슬보다 작게 보인다.

### 2-1. 에너지 (`Intensity` 0~3) — 기존 유지 + 보강

| Intensity | 소리 | 연출 |
|---|---|---|
| 0 | 킥·스네어·햇·베이스 | 배경 기본 밝기 (기존) |
| 1 | + 엇박 플럭 | 경계 링에 엇박마다 작은 눈금 4개가 깜빡 (플럭 위치) |
| 2 | + 오픈 햇 | 배경 밝기 +1단계 (기존), 링 두께 살짝 증가 |
| 3 | + 클랩 | 스네어 플래시가 링 전체로 번짐 |

- 눈금은 링 위 0°·90°·180°·270°에 둔다. 적 진입 방향과 겹쳐도 얇고 짧게 해서 가리지 않게 한다.

### 2-2. 패턴 변형 (`Variation` 0~4)

소리 차이는 작지만 "같은 4마디가 아니다"라는 신호가 필요하다. 링의 **움직임 질감**만 바꾼다.

| Variation | 소리 | 연출 (Z3 경계 링) |
|---|---|---|
| 0 | 원래 패턴 | 기존 그대로 |
| 1 | 8분 드라이브 베이스 | 링이 8분마다 아주 미세하게 숨쉼 (scale ±0.4%) |
| 2 | + 고스트 스네어, 4마디째 16분 필 | 1번 + **4마디째 필에 맞춰 링이 16분으로 빨라지며 밝아짐** → 다음 프레이즈 예고 |
| 3 | 워킹 베이스 + 아르페지오 + 고스트 | 링 위 작은 점 하나가 베이스 음마다 한 칸씩 걸어감 (시계 방향, 마디당 4칸) |
| 4 | 워킹 베이스 + 트레실로 스탭 | 3번 + 스탭(1·2.5·4박)마다 링 세 군데가 동시에 깜빡 |

- 필(2번)은 마지막 16분 전에 끝나므로, 링 연출도 4박 "앤"에서 끝낸다.
- **필요 데이터**: 변형마다 정확한 음표 위치. 아래 4-1의 `BedNotes.g.cs` 생성으로 해결한다.

### 2-3. 콤보 (`Combo` 0~3, 피격 시 0) — 피버 게이지와 같은 의미

| Combo | 소리 | 연출 |
|---|---|---|
| 1 | 16분 햇 | 링 바깥에 얇은 점선 링이 생기고 16분마다 한 칸씩 회전 |
| 2 | 글래스 패드 | 점선 링 + 링 바깥에 은은한 유리빛 후광 (밝기는 패드 화음마다 천천히 호흡) |
| 3 | 벨 아르페지오 | 2번 + 벨 음마다 링 위에서 작은 반짝임 (음 높이 → 각도) |

- 단계는 마디 경계에서만 바뀐다 (`CurrentCombo`가 소리와 같은 타이밍). 올라갈 때 링이 한 번 밝아지고, 떨어질 때(피격)는 아래 2-4의 Hurt 연출이 대신한다.
- 피버 게이지 HUD 색을 콤보 링 색과 맞춰 "콤보가 쌓이면 피버가 온다"는 연결을 보여준다.
- 빌드업·피버 중에는 `Combo` 0 → 점선 링과 후광은 페이드아웃. 피버 연출이 대신한다.

### 2-4. 위기감 (`Tension`, `Danger`, `Hurt`) — Z5 비네트 + Z3 링

| 신호 | 소리 | 연출 |
|---|---|---|
| `Tension` 0.25+ | 현악 패드 | 화면 가장자리 비네트 (진한 남색 → 자주색). 강도 = Tension |
| `Tension` 0.45+ | 엇박 서브 펄스 | 비네트가 엇박 8분마다 살짝 조여졌다 풀림 (킥과 반대 박이라 숨 가쁜 느낌) |
| `Tension` 0.65+ | 애시드 베이스로 교체 | 경계 링이 베이스 8분에 맞춰 미세하게 일그러짐 (반지름 노이즈 ±1.5%) |
| `Danger` (체력 1) | 반주 로우패스 | Z0·Z1·Z3(배경 연출)의 채도와 밝기 -40%, 비네트가 더 안쪽까지. **Z2 손님 연출은 그대로 밝게** (원칙 1) |
| `Hurt()` | 저역 빠짐 0.6초 | 카메라 흔들림 0.15초 + 링이 순간 작아졌다 0.6초에 걸쳐 회복 + 콤보 링 소멸 |

- 비네트 값은 Unity의 목표값이 아니라 **FMOD가 실제로 따라가는 값**을 써야 소리와 맞는다 (Tension은 오를 때 2.0/s, 내릴 때 0.5/s로 따라간다). → 4-2 참고.
- 빌드업·피버 중에는 Tension 0 → 비네트도 0. 피버는 해방감.

### 2-5. 스타일 (`BedStyle`) — Z0 팔레트 + Z1 모티프 (링 모양은 2-0)

| 스타일 | 소리 | 배경 팔레트 (코드 틴트를 스타일 색으로 기울임) | Z1 모티프 |
|---|---|---|---|
| 0 신스팝 | 신스 베이스, 플럭 | 네온 남색·청록 (기존) | 원근 격자선이 킥마다 한 칸 다가옴 |
| 1 라틴 | 콩가·봉고·셰이커, 툼바오 베이스, 마림바 몬투노 | 따뜻한 호박·테라코타 | 큰 원형 문양(태양 무늬)이 클라베 리듬으로 천천히 회전 |
| 2 펑크 | 고스트 스네어, 16분 햇, 슬랩 베이스, 기타 커팅 | 보라·주황 | 사선 줄무늬가 16분마다 미끄러짐, 기타 "찡"(2·4박)에 줄무늬 한 번 번쩍 |
| 3 드리미 (숨 돌리기) | 서브 베이스, 코러스, 벨 | 파스텔 하늘색·연분홍 | 아주 느리게 떠오르는 빛 입자 (기존 숨 돌리기 탈채도와 결합) |

- 전환: `UpcomingStyle`이 다르면 프레이즈 마지막 1박 동안 팔레트를 크로스페이드하고, Z1 모티프는 이전 것이 페이드아웃·다음 것이 페이드인.
- Z1은 알파 0.15 이하. 게임플레이에 방해되면 바로 더 낮춘다.
- 피버 프레이즈는 항상 신스팝 → 피버 팔레트(2-7)가 덮는다.

### 2-6. 숨 돌리기 — 기존 유지

- 배경 탈채도·어둡게, 킥 펄스 절반 (기존) + 드리미 모티프(2-5).
- 숨 돌리기 프레이즈에는 손님 루프가 없으므로 Z2는 비어 있다. 드리미 빛 입자가 그 자리를 아주 약하게 채운다.

### 2-7. 피버 — 프레이즈 하나 전체

| 시점 | 소리 | 연출 |
|---|---|---|
| 빌드업 (앞 프레이즈 4마디째) | 킥 빠짐, 스네어 롤, 플럭 상승 | 아레나 수축 + 롤 깜빡임, 금색 (기존) |
| 피버 첫 박 | 임팩트 | 흰 플래시 + 흰 리플 (기존) |
| 피버 4마디 | 피버 리드, 셰이커, 베이스 5도 | **새로 추가**: 무지개빛 혜성이 킥마다 좌우에서 교차 (Z2, 손님 연출기 재사용). 배경은 코드 틴트 + 채도 최대 |
| 피버 마지막 마디 (아웃트로) | 하강 플럭, 작아지는 스네어 | 혜성 수가 줄고 아래로 휘어짐 |
| 피버 끝 | — | 파란 리플 (기존) → 다음 손님 예고 반짝임과 같은 박 |

## 3. 손님 루프 연출 (12종)

악기별 기본 연출은 [FeatureLoopVisuals.md 6절](FeatureLoopVisuals.md)의 스타일을 쓴다. 여기서는 **루프마다 무엇을 덧붙이는지**를 정한다.

### 3-1. 악기별 기본 연출 (Z2)

### 3-3. 등장·퇴장

- **예고 (1박 전)**: 화면 가장자리 반짝임. 색 = 루프 대표 색 (트럼펫 금색, 휘파람 민트, 말렛 호박, 퍼커션 산호, 신스 분홍, 기타 주황). 지금은 트럼펫/휘파람 2색만 있다.
- **등장**: 첫 음에 해당 영역이 아주 살짝 밝아짐 (Z2 전체 +10%, 1박).
- **퇴장**: 루프가 원래 끝나면 따로 연출하지 않는다. 피버가 루프를 끊는 경우는 바뀐 피버 규칙으로 생기지 않는다.

`MusicReactiveVisuals` 하나에 다 넣으면 커진다. 영역별로 나눈다.

| 컴포넌트 | 영역 | 담당 |
|---|---|---|
| `MusicReactiveVisuals` (기존) | Z0, Z3 킥·스네어, 빌드업, 피버 리플 | 지금 역할 유지 |

  - `MusicReactiveVisuals`가 `LateUpdate` 마지막에 합쳐서 한 번만 적용한다. 축마다 맡은 속성이 달라서(2-0) 대부분 그냥 더하면 되고, 같은 속성을 둘이 건드릴 때만 우선순위를 쓴다: 위기감(일그러짐·Hurt 수축) > 콤보 > 패턴 변형 > 스타일 장식 > 에너지 눈금.
- 모두 `SoundManager`만 읽는다. 서로 참조하지 않는다 (`ArenaStage`는 데이터만 담은 공용 객체). 양보 규칙(3-4)은 각 컴포넌트가 `FeatureSounding`과 `CurrentFeature`를 보고 스스로 판단한다.

### 5-2. 성능 점검과 최적화 (2026-11-24)

**측정** (에디터 Play 모드, ProfilerRecorder, 창 비활성 상태)

| 항목 | 값 | 판단 |
|---|---|---|
| 연출 스크립트 Update + LateUpdate | 평균 약 0.5ms | 평상시 부담은 작음 |
| `LineRenderer.ScheduleGeometryJobs` | 평균 0.1ms, **최대 14.7ms** | 라인 속성을 매 프레임 쓰는 것이 스파이크 후보 |
| LateUpdate / Update 스파이크 | 최대 8.3ms / 5ms | 루프가 처음 나올 때 오브젝트 생성 등 |
| GC 할당 | 프레임당 약 20KB, 360회 | **연출을 꺼도 같음** → 연출 원인 아님 |
| `SceneCamera.Render` | 평균 8.2ms, 최대 25ms | **에디터 Scene 뷰** 비용. 게임 코드와 무관 |

**최적화**
- 손님 루프 연출기 풀을 게임 시작 때 미리 채운다 (`IFeatureEmitter.Prewarm`, 스타일별 `prewarm` 값). 루프가 처음 나올 때 `GameObject`·렌더러를 만들던 스파이크 제거.
- `BedStyleVisuals`: 펑크 조각·격자·햇살 라인 좌표는 시작할 때 한 번만 쓰고, 부모 트랜스폼의 크기·위치·회전만 바꾼다 (라인 두께는 부모 크기의 영향을 받지 않음을 확인). 줄무늬는 16분마다만 다시 계산한다. 색은 바뀔 때만 쓴다. 꺼진 그룹은 한 번 숨긴 뒤 건너뛴다.
- `BedLayerVisuals`: 보이기 상태가 바뀔 때만 `SetActive`.
- `MusicReactiveVisuals`: 링 일그러짐은 8분음표나 세기가 바뀔 때만, `SetPositions` 한 번으로 다시 만든다.
- `TensionVignette`: FMOD 값을 프레임당 한 번만 읽는다. 위기감이 없을 때는 전체 화면 스프라이트를 꺼서 GPU 채우기 비용을 없앤다 (WebGL 빌드에서 특히 중요). 카메라 위치는 흔들릴 때만 쓴다.
- `VisualProfiler`: 연출별 프로파일러 마커 (`Visuals.*`). Profiler 창에서 이름으로 비용을 볼 수 있다.
- 겉보기 변화: 격자선의 위아래 밝기 차이를 없애 균일하게 했고, 펑크 조각 두께는 링 두께를 따라가지 않고 고정했다.

**남은 확인**: 최적화 후 재측정은 하지 못했다 (Unity가 다른 씬을 Play 중이었음). 렉을 볼 때는 Scene 뷰를 닫거나 Game 뷰를 최대화해서 에디터 비용을 빼고 확인할 것.
